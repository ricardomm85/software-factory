# Plan — wire the code-review gate into the board chain (run id 3514805b)

## Goal

Board tasks get no code review today. The CLI already has one:
`run_build_review` in `factory/chains.py` (lenses `review-conventions` + `review-bugs`
→ scorer → gate blocking on findings scored ≥ 50 → bounded fix rounds). Wire that same
sequence into the board chain: after the last test round passes and **before the commit
phase**, reuse it via shared helpers (no duplicated logic), review the **task-branch
diff vs the origin default branch**, fail the chain after N bounded fix rounds
(default 2) with findings still ≥ 50, and add a `config.yaml` `defaults.review: on|off`
toggle (default **on**) used by both call sites of the chain. The `pr_approval` pause
stays after review. Every step traces as phases, exactly like `run_build_review` does.

Baseline: `uv run pytest -q` → 175 passed. It must be green again at the end.

## Non-goals (do NOT touch)

- `factory/web/` (kanban UI) — `phase_label()` already renders `review:*`, `score:*`,
  `gate:*`, `fix:*` phase prefixes; nothing to change there.
- `Board._deliver` and the PR poller (`_poll_prs_loop` / `_pr_state`).
- `run_build_review`'s public signature and behavior (CLI `factory build-review` keeps
  working byte-for-byte; its tests in `tests/test_chain_build_review.py` must pass
  unchanged).
- Prompt templates (`factory/prompts/*.md`) — the loop reuses them as-is.

## Design decisions (already made — do not re-litigate)

1. **One shared loop, two callers.** Extract the body of `run_build_review`'s
   review→score→gate→fix loop into `_review_fix_loop(...)` in `factory/chains.py`,
   parameterized by the `Run` it traces under and the diff base ref. The standalone
   command wraps it with its own run lifecycle; `run_plan_build_test` calls it inline
   under the SAME run (phases appear in the board run's timeline between `test:r1` and
   `checkpoint`/`commit`).
2. **Diff base.** `_working_tree_diff` gains a `base: str = "HEAD"` parameter
   (`git diff <base>` + the same untracked-file collection). The board passes
   `review_base=f"origin/{default}"` — it already computes `default` when cutting the
   task branch. The CLI passes nothing → HEAD. Note `git diff origin/<default>` at
   review time includes the already-landed `commit:plan` plus the uncommitted
   implementation — that is the intended "task branch diff vs origin default branch".
3. **Toggle semantics.** `defaults.review` is read at the two CALL SITES of
   `run_plan_build_test` (board `_execute`, CLI `cmd_plan_build_test`), default **on**
   (`cfg["defaults"].get("review", True)`). The chain function's own `review` parameter
   defaults to **False** (opt-in, exactly like `checkpoint_fn=None` is opt-in) so the
   chain's existing tests and any other callers stay unchanged. This mirrors the
   existing `checkpoint` pattern and satisfies "default on" at the config layer.
4. **Agent resolution stays at call sites** (roster rule: call sites name agents).
   When review is on, both call sites resolve `review-conventions` and `review-bugs`
   (from a new `DEFAULT_REVIEW_LENSES` constant in `chains.py`) and `scorer`. The
   fixer is the builder (`builder_cfg` — "the builder doubles as fixer"; its session
   `{run_id}-builder` continues, same-session correction). If review is on but the
   roster lacks the agents, `resolve_agent` raises `ConfigError` — honest fail-fast:
   the CLI exits 2 with the message; the board's worker puts it on the card note.
   `tests/test_board_logic.py`'s ROSTER therefore gains the three agents.
5. **Failure behavior.** Review not accepted after `review_rounds` (default 2) →
   `run.finish(accepted=False, reason=...)` + `return False, reason` — the same
   pattern as the planner-failure early exit. The checkpoint (`pr_approval` pause),
   commit and deliver phases are never reached. Discovered findings from reviewer
   envelopes are picked up by the board's existing `collect_discovered` (it scans all
   valid envelopes of the run) — no new wiring.
6. **Fixer rollback baseline.** The helper computes `baseline = set(changed_files(repo_dir))`
   at loop start (exactly what `run_build_review` does today) and
   `fixer_allow = baseline | exempt_paths`. In the board chain that baseline is the
   builder's uncommitted work; new unclaimed fixer files still get rolled back.
7. **No new error classes, no raise on a failing `git diff <base>`** — keep the current
   "empty diff → accepted, no changes to review" semantics. The board's base always
   exists by construction (the branch was just cut from it).

c) New `_review_fix_loop`, placed right before `run_build_review`. Move the loop body
of `run_build_review` here VERBATIM except: the early returns replace
`run.finish(...)` + `return`, and the diff call passes `base=diff_base`:

```python
def _review_fix_loop(
    run: Run,
    repo_dir: Path,
    reviewer_cfgs: list[dict],
    scorer_cfg: dict,
    fixer_cfg: dict,
    max_rounds: int,
    agent_fn,
    timeout_s: int,
    exempt_paths: set[str] | None = None,
    env_dir: Path | None = None,
    diff_base: str = "HEAD",
) -> tuple[bool, str]:
    """Reviewers → scorer → gate (>=50 blocks) → bounded fix rounds, re-reviewed
    each round. Shared by ``run_build_review`` (own run, diff vs HEAD) and the
    review wiring inside ``run_plan_build_test`` (same run, diff vs the task
    branch's origin default). Phases trace under ``run``; the caller owns the
    run's settle. The tree's state at loop start (the user's WIP / the builder's
    work) is exempt from the fixer's rollback; ``exempt_paths`` is invisible to
    reviewers and survives every rollback. Returns (accepted, reason)."""
    baseline = set(changed_files(repo_dir))
    fixer_allow = baseline | (exempt_paths or set())
    for round_no in range(1, max_rounds + 1):
        diff = _working_tree_diff(repo_dir, exempt_paths=exempt_paths, base=diff_base)
        if not diff.strip():
            return True, "no changes to review"

        findings: list[dict] = []
        for rcfg in reviewer_cfgs:
            with run.phase(f"review:{rcfg['name']}:r{round_no}", kind="agent", owner=rcfg["name"]) as phase:
                env = call_agent(
                    run, phase, _review_prompt(rcfg["name"], diff), rcfg,
                    output_type=FindingsOutput, agent_fn=agent_fn, repo_dir=repo_dir,
                    timeout_s=timeout_s, env_dir=env_dir,
                )
                phase.log("findings", {"count": len(env.findings)})
                findings.extend(f.model_dump() for f in env.findings)

        with run.phase(f"score:r{round_no}", kind="agent", owner=scorer_cfg["name"]) as phase:
            score_prompt = _correction(
                "score_findings", findings=json_dumps({"issues": findings}), diff=diff,
            )
            scored = call_agent(
                run, phase, score_prompt, scorer_cfg,
                output_type=ScoredOutput, agent_fn=agent_fn, repo_dir=repo_dir,
                timeout_s=timeout_s, env_dir=env_dir,
            )
            phase.log("scored", {"count": len(scored.findings)})

        blocked = [f for f in scored.findings if f.score >= 50]
        with run.phase(f"gate:r{round_no}", kind="code", owner="code") as phase:
            phase.log("review_gate",
                      {"total": len(scored.findings), "blocked": len(blocked), "threshold": 50})
            gate_ok = not blocked

        if gate_ok:
            return True, "no findings scored >=50"
        if round_no == max_rounds:
            return False, (f"{len(blocked)} findings scored >=50 after final round: " + "; ".join(
                f"{f.file}:{f.line} {f.description[:80]} (score {f.score})" for f in blocked))

        findings_json = json_dumps({"issues": [f.model_dump() for f in blocked]})
        with run.phase(f"fix:r{round_no}", kind="agent", owner=fixer_cfg["name"]) as phase:
            fix_prompt = _correction("fix_findings", findings=findings_json, diff=diff[:40000])
            for attempt in range(1, 3):
                fix_envelope = call_agent(
                    run, phase, fix_prompt, fixer_cfg,
                    output_type=BuildOutput, agent_fn=agent_fn, repo_dir=repo_dir,
                    timeout_s=timeout_s, env_dir=env_dir,
                )
                reports = gate_reports(fix_envelope, repo_dir, allow=fixer_allow)
                phase.log("gate_results", {r.gate: r.to_payload() for r in reports})
                if all(r.passed for r in reports):
                    break
                violations = _violations(reports)
                run.log_event(phase.id, "fix_gate_violations", {"violations": violations})
                fix_prompt = f"{fix_prompt}\n\n{_correction('gate_correction', violations='\\n'.join(violations))}"
    return False, "review loop exhausted"  # unreachable: every branch returns
```

d) `run_build_review` becomes a thin wrapper — same signature, same docstring intent,
run lifecycle stays here:

```python
def run_build_review(conn, repo_dir, reviewer_cfgs, scorer_cfg, fixer_cfg, max_rounds=2,
                     agent_fn=run_pi_streaming, timeout_s=600, exempt_paths=None, env_dir=None):
    """Multi-lens review of the working-tree changes: reviewers → scorer → gate (>=50
    blocks) → bounded fix rounds with the fixer, re-reviewed each round. The loop
    itself is :func:`_review_fix_loop`, shared with the board chain's inline review.
    ..."""
    run = Run.create(
        conn, request="build-review: working-tree changes", agent=reviewer_cfgs[0]["name"],
        model=reviewer_cfgs[0]["model"], repo=str(repo_dir),
    )
    try:
        accepted, reason = _review_fix_loop(
            run, repo_dir, reviewer_cfgs, scorer_cfg, fixer_cfg, max_rounds,
            agent_fn, timeout_s, exempt_paths=exempt_paths, env_dir=env_dir, diff_base="HEAD",
        )
    except BaseException as exc:
        run.finish(accepted=False, reason=f"{type(exc).__name__}: {exc}")
        raise
    run.finish(accepted=accepted, reason=reason)
    return accepted, reason
```

## Acceptance criteria

1. `uv run pytest -q` fully green: the 175 pre-existing tests pass (only
   `tests/test_board_logic.py`'s ROSTER constant was extended) plus the 8 new tests.
2. Board chain with review on traces, in order: `plan, plan_gates, handoff,
   commit:plan, build:r1, test:r1, review:review-conventions:r1, review:review-bugs:r1,
   score:r1, gate:r1[, fix:r1, review:*:r2, score:r2, gate:r2], checkpoint, commit,
   deliver` — verified by test 1 (a) and the phase-order assertions in (b).
3. Exhausted fix rounds (default 2) → chain returns `(False, "…findings scored >=50…")`,
   session `failed`, no checkpoint/commit/deliver — test 3 (a).
4. `defaults.review: off` (or `--no-review`) → no review phases, no review agent calls
   — tests 4 (a) and the board toggle test (b).
5. The board passes `review_base="origin/<default>"` and the resolved lens/scorer
   agents to the chain — test (b); the review diff covers the task branch vs that base —
   test 5 (a).
6. `run_build_review`'s own tests (`tests/test_chain_build_review.py`) pass unchanged —
   the extraction is behavior-preserving.
7. `factory/chains.py` contains exactly ONE implementation of the review→score→gate→fix
   loop (`_review_fix_loop`); `run_build_review` and `run_plan_build_test` only wrap it.
8. Nothing outside the plan's file list changed: no `factory/web/`, no `_deliver`, no
   poller, no prompt templates.
